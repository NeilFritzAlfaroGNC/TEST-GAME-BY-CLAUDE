# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Food Heroes** — an educational drag-and-drop game (Godot 4.6, GDScript) that teaches the Filipino **Go / Glow / Grow** food groups. Built as a gray-box prototype: gameplay is complete but in-game visuals are still colored `ColorRect` boxes on purpose ("art last"). The **art phase has started with UI**: the Main Menu buttons are themed via `assets/ui/menu_theme.tres` (9-patch `StyleBoxTexture`s from Kenney's UI Pack, CC0 — source PNGs copied into `assets/ui/`). See `README.md` for player-facing details and the phase-by-phase mapping to the original dev reference.

## Running & validating (no unit-test framework)

Godot is **not on PATH**. The editor/runtime executable is:
```
C:\SHIZ\Godot_v4.6.3-stable_win64.exe
```

**The standard check is one command, SIX steps**, PASS/FAIL summary, exit code 0/1:

```powershell
powershell -ExecutionPolicy Bypass -File tools\test.ps1
```

1. **Import** — regenerates the `.godot/` cache.
2. **Logic smoke test** (`tools/smoke_test.gd`, standalone via `--headless --path "D:\TEST" -s res://tools/smoke_test.gd`) — pure-logic assertions: star math per difficulty, boss cadence, level clamping, nutrient coverage, difficulty tables, `Layout`'s geometry at several aspect ratios and safe-area insets, `WaveDirector`'s `track`/`untrack`/`needed_groups` bookkeeping, `ScoreKeeper`'s streak math, and the whole DB layer (unlock chain, best-score upsert, settings, per-group accuracy) — all against a **throwaway** `user://smoke_test.db`, never the real save. Note: `-s` script mode still loads the autoloads, but a child added to root during `_initialize` does **not** get `_ready` — the test calls `DB`-instance `_open()` directly for that reason.
3. **Solvability invariant** (`tools/invariant_test.gd`, run as a scene: `tools/invariant_test.tscn`) — drives the *real* `scenes/Game.tscn` through its real spawn/despawn paths (including a full boss fight) and asserts, every phase, that `WaveDirector`'s tracked weaknesses match the monsters actually in the `"enemies"` group. Step 2 unit-tests `track`/`untrack`/`needed_groups` in isolation; nothing else proves `Game.gd` actually *calls* them in pairs — dropping either call from `_spawn_enemy`/`_despawn` would pass every other step clean while quietly making a level unwinnable, so this gets its own dedicated gate. Isolated to a throwaway `user://invariant_test.db` — see "Testing & the solvability invariant" below.
4. **Headless run: `Game.tscn`** — the only level scene now; ~2.5s (`--quit-after 150`).
5. **Headless run: `MainMenu.tscn`**.
6. **Headless run: `HowToPlay.tscn`**.

The individual steps, when you need just one:

```powershell
# Import (regenerates .godot/ cache; run after adding resources)
& "C:\SHIZ\Godot_v4.6.3-stable_win64.exe" --headless --path "D:\TEST" --import

# Run one scene for ~N frames to catch runtime errors
& "C:\SHIZ\Godot_v4.6.3-stable_win64.exe" --headless --path "D:\TEST" "res://scenes/Game.tscn" --quit-after 150
```

When checking a headless run, filter for **real** failures and ignore noise. `tools/test.ps1`'s `$failPattern` is:
`SCRIPT ERROR | Parse Error | Invalid access | Invalid call | null instance | Cannot find | Condition ".*" is true`.
That last alternative is deliberately **targeted**, not a bare `ERROR:` match — it exists to catch a native `CHECK`/`ERR_FAIL_COND` failure, which is how a silent NaN bug in `Layout.refresh()` (see Architecture below) surfaced after passing every headless run "clean" for several tasks. A blanket `ERROR:` match is not the fix: the documented-benign `ObjectDB instances leaked at exit` and `resource still in use: music.wav` lines below are themselves ERROR-level, so matching them would fail every run and train everyone to ignore red.

Known benign noise: a `--quit-after` run logs `resource still in use: music.wav` / "ObjectDB instances leaked at exit". This is only the audio autoload being force-killed mid-playback; it does **not** happen on a normal window close and is not a real leak. Step 3 additionally logs `WARNING: Layout: DisplayServer reported a (0.0, 0.0) window; falling back to...` — expected and benign under `--headless` (see Architecture); it would only be a real bug on a device.

Do **not** launch `--headless --editor`: `--quit-after` does not quit the *editor*, so the process stays alive in the background holding the `godot-sqlite` DLL — subsequent `--import` runs then fail with `Error copying library` / `GDExtension dynamic library not found`. If imports suddenly fail that way, kill the stray Godot process. A force-killed instance also leaves `~libgdsqlite…TMP` copies in `addons/godot-sqlite/bin/`; they are the extension's copy-on-load leftovers, already gitignored (`*.TMP`), and safe to delete. (Editor-only chores like re-saving scenes for uid headers must be done in the editor UI.)

Headless cannot simulate mouse drag — to verify gameplay feel (drag, zap/heal/slam, sound) open the project and press **F5**.

### Testing & the solvability invariant

**Tests must NEVER write to the real `user://foodheroes.db`.** Both test drivers isolate to a throwaway file: `tools/smoke_test.gd` runs in `-s` script mode against `user://smoke_test.db`; `tools/invariant_test.gd` runs as an ordinary scene (so all four autoloads boot first and `DB._open()` briefly connects to the real save, same as any headless scene run) but its `_ready()` calls `_isolate_db()` — the *first* statement, before `GameData.start_level` or `Game.tscn` is instantiated — which closes that connection and reopens `DB` against `user://invariant_test.db`; `_finish()` deletes that file on every exit path, pass or fail. If you add a new headless driver that exercises gameplay (anything that can reach `DB.record_answer` / `record_level_result`), it needs the same file-level redirect, not just a decoy key — a `--quit-after` force-kill is a real, documented occurrence here, and a decoy key inside the live save can still strand a row if the process dies before cleanup.

**The solvability invariant is the worst failure mode in the design:** `BeltManager._ensure_needed()` runs every frame, cap-free, and instantly spawns a food for any group the belt's injected Callable reports as needed. That Callable resolves to `Game._needed_groups()`, which in turn reads `WaveDirector.needed_groups()` (or, during a boss, the still-missing meal groups). The only thing keeping that list honest is that every `director.track(group)` in `Game._spawn_enemy` is matched by exactly one `director.untrack(group)` in `Game._despawn`. If a `track`/`untrack` pair is ever dropped, a level can go from fully playable to silently unwinnable — a child facing a monster with no way to feed it, or the belt burning its 6-food cap guaranteeing food for a monster that no longer exists — and nothing about the game *looks* broken. This is exactly why step 3 exists as its own gate rather than relying on more headless scene coverage: a scoped test proved that deleting `director.untrack` from `_despawn` still leaves steps 4-6 reporting "clean".

## Regenerating audio

All sound is synthesized locally — there are **no downloaded assets**. To change a sound, edit and re-run the generator (pure Python stdlib), then re-import:
```powershell
python tools/generate_audio.py     # writes audio/*.wav
```

## Architecture (the big picture)

**Four autoloads hold everything that must outlive a scene change** (registered in `project.godot`, in this init order — `Layout` **must** load first, see below):
- `Layout` (`scripts/Layout.gd`) — the single authority for every on-screen coordinate: hero position, belt lane, food stack, monster spawn line and lanes, HUD strip. It is a **pure function of the viewport and the safe area** — `design_scale`, `visible_size`, `safe_in_design` and `compute(view, safe) -> Dictionary` are all `static func`s with no `DisplayServer`/autoload reads — which is what makes the whole layout testable headlessly at any aspect ratio (`tools/smoke_test.gd` calls `compute()` directly). **Keep it that way**: anything added to `Layout.gd` as a `static func` must stay pure, or the headless coverage stops meaning anything. The impure part is `refresh()` (called from `_ready()` and on every `size_changed`): it reads the live `DisplayServer.window_get_size()` / `get_display_safe_area()`, converts to design units, and republishes into `Layout.m`, emitting `changed`. **Gotcha:** `DisplayServer.window_get_size()` reports `(0, 0)` under `--headless`, and dividing by that ratio would turn every metric into NaN — silently, since GDScript doesn't throw on it. That NaN shipped unnoticed through several tasks before it was caught, because nothing was watching for it. `refresh()` now guards it: a non-positive window axis falls back to `BASE` (1152×648) and `push_warning`s once, rather than staying silent. The design box is **landscape-only**, height fixed at 648, width growing from 1152 (16:9) to ~1512 (21:9) — `Layout.m["view"]` is that visible size, read directly by e.g. `LevelSelect.gd`'s dynamic grid. Consumers that build something once (not every frame) — `BeltManager`'s drawn conveyor, `Game`'s hero/camera placement, `LevelSelect`'s grid — must connect to `Layout.changed` and rebuild; things computed every frame (`Food`, `BeltManager._layout()`) just re-read `Layout.m` and need no signal.
- `DB` (`scripts/Database.gd`) — persistence layer. Backend is **SQLite only**, via the `godot-sqlite` GDExtension committed in `addons/godot-sqlite/` (Windows + Android binaries). The `SQLite` class is still reached by string (`ClassDB.instantiate("SQLite")`); `_open()` verifies the class exists and the DB opens with **runtime checks, not `assert`s** (asserts are stripped from release exports) — on failure it `push_error`s, shows an `OS.alert`, and quits. Because `quit()` only lands at end of frame, the query helpers guard `_db == null` and public methods return safe defaults, and every query's return value is checked (`push_error` on failure). Tables: `meta` (high score, mute flag, `tutorial_done`), `progress` (`PRIMARY KEY(difficulty, level)` → best_score, stars, completed), and `accuracy` (`PRIMARY KEY(difficulty, "group")` → correct/wrong counts, upserted by `record_answer(difficulty, group, was_correct)` — the per-group evidence-of-learning record `ResultScreen` reads back through `get_accuracy(difficulty)`). There is **no run history / recent-scores feature** — the old `runs` table is dropped on open. The high score is shown on the in-level HUD and the Result screen (it was removed from the Main Menu). Must load after `Layout`, before `GameData` (which calls it on `_ready`).
- `GameData` (`scripts/GameData.gd`) — the food database (`FOODS` by group, `FOOD_NUTRIENTS`, and `NUTRIENT_GROUPS`: nutrients that map to exactly one group, so a Hard-mode monster asking for one has a single correct answer), the 15-row `LEVELS` table (1-based; see "Levels & difficulty as a teaching ladder" below), `DIFFICULTIES` (Easy/Medium/Hard), and the **live run state** (`current_difficulty`, `current_level`, `score`, `lives`, `starting_lives`, `last_result`, `last_stars`, `tutorial_mode`). State lives here, *not* in the game scene, so it survives `change_scene_to_file`. `start_level(difficulty, number)` resets the run; `start_tutorial()` primes the guided first run; `record_result(won)` computes stars from lives and writes scores+progress through `DB`.
- `Audio` (`scripts/Audio.gd`) — one-shot SFX + looping music, all null-guarded so missing files never crash the game. Each SFX has a small **voice pool** (`MAX_VOICES_PER_SFX`) so rapid repeats overlap instead of cutting off. Runs with `PROCESS_MODE_ALWAYS` so music and menu clicks keep working while the tree is paused. Holds the **mute** state (`muted` / `set_muted` / `toggle_muted` → Master bus mute), persisted through `DB.get_setting_int/set_setting_int` ("muted" in the `meta` table) and toggled by the Main Menu's **Sound** button.

**SQLite is required:** the `godot-sqlite` addon (`.gdextension` + platform binaries for Windows/Android) is committed in `addons/godot-sqlite/`, so no setup step is needed. There is no JSON fallback — if the extension fails to load, `DB._open()` alerts and quits (a runtime check that also works in release builds).

**Scene flow:** `MainMenu.tscn` → `LevelSelect.tscn` → `Game.tscn` (one level) → `ResultScreen.tscn` → (Next / Retry / Level Select / Menu). `ResultScreen` reads `GameData.last_result` (win/lose), `last_stars`, and `DB.get_accuracy(current_difficulty)` for a per-group "practise your X foods" line. The menu also links to `HowToPlay.tscn` (static instructions + a "Play Tutorial" button). `Game.tscn` is the **only** level scene — the old `Main.gd`/`Main.tscn` this replaced was deleted once every menu was repointed here; there is nothing left for a stray reference to silently fall back to.

**Levels & difficulty as a teaching ladder:** `GameData.LEVELS` has **15 rows**; `GameData.is_boss_level(n)` is `n % BOSS_EVERY == 0` (`BOSS_EVERY = 5`), so levels **5, 10 and 15** are boss fights — nothing is hand-listed, adding a 16th level would not need a boss-list update. Each row still carries a `correct_group` field (and `tools/smoke_test.gd` still asserts it names a real group) but it is **vestigial for spawning** — a leftover of the pre-rebuild per-level model. `Game._spawn_enemy` never reads it; each monster's weakness is `GameData.random_group()` (or, during the tutorial, always `"Go"`). What actually varies per difficulty (`GameData.DIFFICULTIES`) is `lives` / `speed_mult` / `spawn_mult` / `enemy_bonus` / `score_mult`, **plus `monster_label` and `show_food_color`, which make difficulty a teaching ladder rather than just speed knobs**: Easy tints belt foods by group and labels monsters with their group name; Medium drops the colour tint (same group label) so the child must read the food's name; Hard swaps a monster's label to a nutrient about half the time (`WaveDirector.pick_label_mode`, `NUTRIENT_SHARE = 0.5`) so the child has to chain food → nutrient → group instead of matching a label directly.

**Per-monster weakness (replaces the old one-decision-per-level model):** each spawned `Enemy` carries its **own** `weakness` (the food group that defeats it) and `label_mode` ("group" or "nutrient"), so a level is no longer "feed Go foods for a while" but a sequence of independent classification decisions, one per monster. A correct food defeats the **closest** enemy whose `weakness` matches (`Game._closest_matching`).

**First-run tutorial (`GameData.tutorial_mode` + `Game.gd`'s tutorial branch):** the menu's Play button checks `DB.get_setting_int("tutorial_done", 0)` — if unset it calls `GameData.start_tutorial()` (Easy, 5 lives, `TUTORIAL_*` pacing consts) and loads `Game.tscn` instead of LevelSelect. `Game._start_level`'s tutorial branch shows the `TUTORIAL_PAGES` intro one page at a time through the **lesson popup** (`_tutorial_intro_active` reroutes `_on_continue_pressed`), then starts a single slow all-Go wave; monsters and the belt only start after the last page (`_advance_tutorial_intro`). Completing it sets `tutorial_done=1`, clears `tutorial_mode`, and goes to LevelSelect **without recording a result** (the tutorial is not level 1). Losing it just restarts it; PauseMenu's Retry re-primes via `start_tutorial()` (not `start_level`, which clears the flag). `HowToPlay.tscn`'s "Play Tutorial" can rerun it any time. **`game_active` is set `true` before the intro pages are shown**, not after — so `Game.gd` exposes `can_pause()` (`game_active AND NOT _tutorial_intro_active`) rather than letting `PauseMenu` read `game_active` raw, or Esc during the intro would layer the pause overlay over the lesson popup.

**Pause (`scripts/PauseMenu.gd` on `Game.tscn`'s `PausePopup/Root`):** Esc (`ui_cancel`) or the HUD **Pause** button toggles `get_tree().paused`, which freezes enemies, both spawn timers, belt foods, and camera shake. The overlay's `process_mode = 3` (ALWAYS) is what keeps its Esc handling and buttons alive while paused — don't remove it. `_pause()` refuses when `can_pause()` is false (lesson popup, tutorial intro, or game over). Its Retry / Level Select / Main Menu buttons **must unpause before `change_scene_to_file`** or the next scene loads frozen (`_leave()` does this). Retry reloads `get_tree().current_scene.scene_file_path` rather than a hardcoded path — a deliberate scene-agnostic touch left over from when this script was shared between `Main.tscn` and `Game.tscn`; it needed no change for the cutover. Leaving mid-level records no result — progress only saves through `GameData.record_result`.

**`LevelSelect.gd`** picks a difficulty (Easy/Medium/Hard) and a numbered level (1–15), then calls `GameData.start_level(...)`. It builds the level grid **dynamically in code** from `DB.is_level_unlocked` / `DB.get_level_progress`; levels unlock in order **per difficulty** (clear level N to open N+1; each difficulty is an independent track). Every boss tile (5/10/15) gets a "BOSS n" badge and a purple tint. The grid's **column count** adapts to `Layout.m["view"].x` rather than a fixed number, so 16 tiles (15 levels + a "coming soon" slot) fit within the design box's fixed 648-unit height on any supported aspect ratio without the tile size shrinking below its ~15mm-equivalent 150 design units.

**`Game.gd` plays exactly one level** (the one chosen in LevelSelect) and is a **thin orchestrator**: in `_ready` it code-creates five dependency-free child components and wires them together, keeping only the cross-script contract, the top-level win/lose flow, and HUD refresh calls for itself.
- **`WaveDirector`** (`scripts/WaveDirector.gd`) — the level/wave/boss state machine: what spawns and when, and `needed_groups()` / `track()` / `untrack()`, the live half of the solvability invariant (see "Testing & the solvability invariant" above). Signals `wave_started`, `level_cleared`, `boss_ready`.
- **`ScoreKeeper`** (`scripts/ScoreKeeper.gd`) — score, streak multiplier (`streak_mult`, every `STREAK_STEP` consecutive correct answers raises it, capped at `STREAK_CAP`), and a per-group `{correct, wrong}` tally for one run. Deliberately free of engine and DB dependencies so `tools/smoke_test.gd` can exercise it headlessly; `Game.gd` forwards each result to `DB.record_answer` itself.
- **`HudController`** (`scripts/HudController.gd`) — all HUD text and colour formatting, so the orchestrator never formats a string. Its internal setter is named `_put`, not `_set` — `Object` declares a virtual `_set(StringName, Variant) -> bool`, and colliding with it is a hard parse error that takes down every script depending on this one.
- **`BeltManager`** (node "Belt") — everything conveyor-side (see below).
- **`FxManager`** (node "Fx") — every procedural effect (see below).

None of the five component scripts declares `class_name` (it would register project-wide global symbols for something only `Game.gd` instantiates), so `Game.gd` `preload`s them as consts and holds the instances in **untyped** vars — annotating them (`var director: WaveDirector`) makes GDScript's static checker reject the file. `Layout.changed` re-anchors the Hero, camera and `FxManager`'s cached hero-home whenever the viewport changes (`Game._reanchor`); belt foods and monster lanes re-derive from `Layout.m` every frame instead and don't need the signal.

**Cross-script contract (important when renaming or restructuring) — the two halves are NOT symmetric:**
- **`Food.gd` is unchanged from the pre-rebuild contract:** it reaches the controller via `get_tree().current_scene` and calls `food_dropped_on_hero(self)`, and locates the hero with `current_scene.get_node("Hero")`. This only works because **`Game` is the active scene** and exposes that method, and the hero **must remain a direct child of `Game` named exactly `Hero`**. The param is passed **untyped** on purpose — typing it (e.g. `food: Node`) would make GDScript's static checker reject `food.food_group` / `food.label`.
- **`Enemy.gd` was rewritten to remove scene-tree reaching entirely.** It has no `get_tree`, `current_scene` or `get_node` calls anywhere. Everything — the group weakness, the label mode, the speed, the walk target, and the "I reached the hero" callback — is **injected** through `setup(group, mode, speed, target_x, on_reach: Callable)`, called by `Game._spawn_enemy` right after `add_child`. An enemy reaching its target calls `on_reach.call(self)` (wired to `Game._on_enemy_reached`, or `Game._boss_reached_hero` for the boss) instead of calling a named method on the controller. Do not reintroduce scene-tree reaching into `Enemy.gd` when touching it — that was a deliberate Task 8 change, not an oversight.

**Enemy lifecycle & the level state machine:** spawned enemies join the `"enemies"` group (the boss uses a separate `"boss"` group, and never enters `WaveDirector`'s track/untrack bookkeeping). `Game._despawn(enemy)` removes it from the group *before* `queue_free` (so the count is right that same frame), calls `director.untrack(enemy.weakness)`, then `director.on_enemy_removed.call_deferred()`. `WaveDirector.on_enemy_removed` is the driver: once `enemies_to_spawn <= 0` and the tracked weaknesses list is empty, it starts the next wave, emits `boss_ready`, or emits `level_cleared` — see boss levels below. `track`/`untrack` **must always pair** with every enemy create/free path; see "Testing & the solvability invariant" above for why.

**Boss levels & waves (`Game.gd` + `WaveDirector` + `GameData.BOSS_*`):** every `BOSS_EVERY`-th level (5, 10, 15) is a boss fight, not a flat batch. `WaveDirector.start`/`_next_wave` runs `BOSS_WAVES` (3) waves of ordinary weakness-bearing monsters, then emits `boss_ready` once the last wave is clear; `Game._on_boss_ready` calls `_spawn_boss()`, which arms `_boss_active` and a big, slow `Enemy` (reusing `Enemy.tscn`, scaled and tinted) in the `"boss"` group. **Ordering inside `_spawn_boss` is deliberately defensive:** `_meal_needed` is filled *before* `_boss_active` is set `true`, because `_needed_groups()` starts returning `_meal_needed` the instant that flag flips and `BeltManager._ensure_needed()` calls it every frame — filling second could in principle let the belt guarantee an empty list for a frame if `_spawn_boss` ever grows a yield point between the two lines (today, with no such await, GDScript's single-threaded `_process` ordering means it can't actually happen — but the ordering is the correct defensive default regardless). You beat the boss by **building a balanced meal**: feeding one food from *each* group in `GameData.BOSS_MEAL_GROUPS` (Go + Grow + Glow). While `_boss_active`, `food_dropped_on_hero` routes to `Game._feed_boss` instead of the normal weakness check — any group is a valid answer, a still-needed group lands a hit (tracked by erasing from `_meal_needed`), a duplicate is rejected without stunning or touching the accuracy table (it was read correctly, just already on the plate). The boss reaching the Hero costs a life and knocks it back rather than despawning it (`_boss_reached_hero`). `WaveDirector` has no signal for "boss defeated" (only `boss_ready`, meaning "time to spawn it"), so the win path `_feed_boss` → `_boss_defeated` → `_level_complete` is wired directly in `Game.gd`.

**Food conveyor belt & the solvability invariant (`scripts/BeltManager.gd`):** foods are **spawned onto a left→right conveyor belt** (`scenes/Food.tscn` + `Food.gd`), not fixed boxes. `BeltManager._layout()` runs every frame and assigns each food a right-anchored `target_x` (`Layout.m["stack_front_x"]`, `Layout.m["stack_spacing"]`) it slides toward, so foods **stack** against a stop point instead of running off-screen. **Spawning is two-tier:** a 1s timer adds **1–2 random foods per tick** capped at `Layout.MAX_FOODS` (6, fixed regardless of viewport), while **`_ensure_needed()` runs every frame** and instantly (cap-free) spawns a food of any group its injected Callable reports as needed — never remove that guarantee or a level/boss can become unwinnable. `Game._ready` wires that Callable to `Game._needed_groups()`, which returns `director.needed_groups()` normally or the still-missing boss meal groups. New foods **enter spaced ≥`stack_spacing` behind the current left-most food** (`_entry_x`) so they never overlap while sliding in. Food nodes live in **`Game`'s `$Foods` container** (`foods_container`; `PauseMenu` iterates it — don't move ownership). All drawn coordinates (`stack_front_x`, `spawn_x`, `belt_y`, `belt_top`) come from `Layout.m`, not fixed constants — the belt's own drawn band/edge/stripes are rebuilt on `Layout.changed` since they're built once, not every frame.

**Food lifetime & drag (`Food.gd`):** a food's `age` clock **starts only once it has arrived at an on-screen slot** (`_activated`), and **pauses while the food is held** (resumes on release / glide-back) — so the full countdown, blink, and despawn are always visible and a dragged food never expires in-hand. Untouched, it lasts `LIFETIME` (3s) and **blinks** for its final second (`BLINK_AT` 2s). Its lane Y reads `Layout.m["belt_y"]` fresh each frame rather than caching it, since `Layout.m` can be refreshed on a resize. Only **one food is draggable at a time** (a mouse-press is ignored if any sibling is already `dragging`). Releasing a food that isn't consumed **glides it back to the exact slot it was grabbed from** (a `RETURN_TIME` tween sets `returning`) — its slot stays reserved because `_layout` ranks a `dragging`/`returning` food by its frozen `target_x` (`_rank_x`), so the other foods don't slide into the gap. `food_dropped_on_hero(food)` **returns bool** (true = consumed/removed, false = glides back — covers both a drop away from the Hero and a rejected wrong food).

**Special attack effects (`scripts/FxManager.gd`)** are fully procedural (no assets): Go = `Line2D` lightning (`_zap`), Glow = green pulse + expanding ring (`_heal`), Grow = shockwave + camera shake + hero lunge (`_slam`). `Game` calls `fx.play_attack(group, target)` / `fx.shake(...)` / `fx.nutrient_popup(...)`. The shake is driven by the `Camera2D` handed over in `fx.setup(hero, cam)` via FxManager's `_process`; `Game._reanchor` re-calls `fx.setup` on every `Layout.changed` so the cached hero-home doesn't go stale after a resize. The hero's slam-lunge and heal-tint tweens are **single-flight** (`_hero_move_tween` / `_hero_tint_tween`): a new effect kills the previous tween and re-anchors to `_hero_home`, so overlapping effects can never leave the hero drifted off its home position. A correct food also floats a rising `+nutrient` label (`fx.nutrient_popup`) whose text comes from `GameData.food_nutrient()` (the `FOOD_NUTRIENTS` map).

**Accuracy / educational telemetry:** every classification decision — correct or wrong, **outside the boss fight** — goes through `DB.record_answer(difficulty, group, was_correct)`. Two cases must NOT reach it, and `Game.food_dropped_on_hero` gates on the live `"enemies"` group (never `needed_groups()`, so the two checks can't drift) to tell them apart: (1) no monster is on screen at all (between waves, or the wave's last monster just died) — a timing artifact, not a knowledge failure, so it shows a neutral "wait for the next one" message and records nothing; (2) any feed while `_boss_active` — every group is a valid answer during the boss, so it isn't a classification decision at all. `ResultScreen` renders the resulting per-group percentages via `_accuracy_line()`, naming the worst group below 80% as worth practising.

## Godot conventions & gotchas specific to this project

- **The food group is a bare string** `"Go"` / `"Glow"` / `"Grow"`, used three ways: dict key into `GameData.FOODS`, key into `GameData.group_color()`, and compared against a monster's `weakness` (`Enemy.gd`) — not a level's `correct_group`, which is vestigial (see "Levels & difficulty as a teaching ladder" above). Spelling must match exactly across `GameData`, scenes, and code.
- **Clicks/drag require care:** every interactive `Area2D` needs a `CollisionShape2D`, and any `ColorRect`/`Label` drawn over it (including the full-screen `Background`) must set `mouse_filter = 2` (Ignore) or it swallows the click before physics picking sees it. `Game._ready` also sets `get_viewport().physics_object_picking = true`.
- **Gray-box is intentional.** When the art phase comes, replace each `ColorRect` with a `Sprite2D` but keep node names and attached scripts identical so the contracts above keep working.
- **Commit Godot metadata:** `*.import` (e.g. `audio/*.wav.import`) and `*.uid` files must be committed alongside their source; `.godot/` is the cache and is gitignored. **`.uid` sidecars are for `.gd` scripts only** — a `.tscn` scene carries its UID inline in its own `[gd_scene uid=...]` header and never gets a separate `.uid` file. Opening the project in the editor re-saves `.tscn` files with added `uid`/`unique_id` fields — that's expected, don't revert it.
- GDScript is **tab-indented**. Keep the `config/features` version in `project.godot` aligned with the editor version (4.6).
